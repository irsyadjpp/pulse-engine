Dokumen ini mendefinisikan standar enterprise, kerangka kepatuhan, dan persyaratan regulasi yang harus dipenuhi oleh Pulse Engine sebagai platform marketplace asuransi di Indonesia.

# 2. Regulatory Landscape

Pulse Engine harus memenuhi persyaratan regulasi berikut.

## 2.1 Indonesian Regulations

### Undang-Undang Perlindungan Data Pribadi (UU PDP)

**Nomor:** UU No. 27 Tahun 2022

**Scope:** Perlindungan data pribadi warga negara Indonesia.

**Key Requirements:**

* Consent management untuk pemrosesan data pribadi.
* Data minimization - hanya mengumpulkan data yang diperlukan.
* Purpose limitation - data hanya digunakan untuk tujuan yang dinyatakan.
* Data accuracy - menjaga akurasi data pribadi.
* Storage limitation - retention period yang jelas.
* Integrity and confidentiality - perlindungan data.
* Rights of data subjects - hak akses, koreksi, penghapusan.

**Implication for Pulse Engine:**

* Implementasi consent tracking untuk setiap pemrosesan data.
* Enkripsi data pribadi (PII) di rest dan transit.
* Audit trail untuk seluruh akses data pribadi.
* Data retention policy sesuai ketentuan.
* Mekanisme untuk menanggapi permintaan hak subjek data.

# 3. Security & Compliance Architecture

## 3.1 Security Architecture Principles

### Defense in Depth

Implementasi multiple layers of security controls:

```
Network Security
    ↓
Application Security
    ↓
Data Security
    ↓
Identity & Access Management
    ↓
Monitoring & Detection
```

### Least Privilege

* Principle of least privilege untuk seluruh user dan service account.
* Role-based access control (RBAC).
* Regular access review dan certification.

### Separation of Duties

* Developer tidak memiliki akses ke production.
* Operations tidak memiliki akses ke application code.
* Security team independent dari development team.
* Independent audit dan review.

---

## 3.2 Data Classification

### Classification Levels

| Level | Description | Examples | Protection Requirements |
| ----- | ----------- | -------- | ----------------------- |
| **Restricted** | Data yang sangat sensitif, kerusakan/kebocoran berdampak serius | Policyholder PII, Payment credentials, Medical records | Enkripsi end-to-end, strict access control, audit logging |
| **Confidential** | Data internal yang sensitif | Customer information, Financial transactions, Quote history | Enkripsi at rest dan transit, role-based access, audit trail |
| **Internal** | Data untuk penggunaan internal | Product catalog, Business reports, System logs | Access control, integrity checks, backup |
| **Public** | Data yang dapat dipublikasikan | Product information, Marketing materials | Availability, integrity |

### Data Protection Requirements

#### Data at Rest

* **Restricted:** AES-256 encryption, HSM untuk key management.
* **Confidential:** AES-256 encryption atau database-level encryption.
* **Internal:** Database-level encryption atau filesystem encryption.
* **Public:** Optional encryption.

#### Data in Transit

* **Internal Communication:** mTLS mutual TLS.
* **External Communication:** TLS 1.3 minimum.
* **Legacy Systems:** VPN atau dedicated connection dengan encryption.
